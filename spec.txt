================================================================================
 Movie Maker - 텍스트 시나리오 / 정지 이미지 기반 동영상 생성 시스템
 Specification v0.1   (작성일: 2026-11-20)
================================================================================

1. 개요
--------------------------------------------------------------------------------
1.1 목적
  사용자가 입력한 (a) 텍스트 시나리오, (b) 정지 이미지(사진), 또는 (a)+(b)를
  이용하여 동영상(MP4)을 생성하는 클라이언트-서버 구조의 프로그램을 개발한다.

1.2 입력 모드
  - TEXT_ONLY   : 시나리오만 입력  -> (키프레임 이미지 생성) -> T2V 또는 I2V
  - IMAGE_ONLY  : 사진만 입력      -> I2V (기본 모션 프롬프트 사용)
  - TEXT_IMAGE  : 시나리오 + 사진  -> 프롬프트가 붙은 I2V

1.3 생성 엔진 정책
  - 서버는 자체 동영상 생성 솔루션(로컬 오픈 웨이트 모델)을 기본으로 한다.
  - 외부 AI 동영상 API(Veo, Kling, Runway, Luma 등)도 동일 인터페이스로 사용 가능.
  - 엔진 교체는 설정(환경 변수)만으로 가능해야 한다 (VideoProvider 추상화).

2. 추천 오픈소스 (2026년 중반 기준, 도입 전 최신 버전/라이선스 재확인 필요)

3. 시스템 아키텍처
--------------------------------------------------------------------------------
  [Client: Web (React TypeScript)]
     │  REST (작업 생성/조회) + SSE (진행률 스트림)
     ▼
  [API Server: FastAPI]  ── DB(MySQL→PostgreSQL), Storage(Local→MinIO/S3)
     │  작업 큐잉
     ▼
  [Broker: Redis]  ←→  [Celery Worker (GPU 노드)]
                          ├─ 1. 시나리오 분석 (LLM) → shot list JSON
                          ├─ 2. 키프레임 생성 (FLUX)        ※ 이미지 없을 때 (선택)
                          ├─ 3. 샷별 영상 생성  ← VideoProvider
                          │       ├─ comfyui  : 로컬 Wan/LTX (ComfyUI API)
                          │       ├─ mock     : FFmpeg 테스트 영상 (GPU 없이 개발용)
                          │       └─ external : 외부 AI API (어댑터)
                          ├─ 4. TTS + 자막                  (선택)
                          └─ 5. FFmpeg 합성 → 최종 MP4

  설계 원칙
  - VideoProvider 추상화: generate(shot, image_path) -> 영상 파일 경로
  - 샷 단위 생성 후 연결: 모델 1회 생성 길이(5~10초) 한계 극복.
    이전 샷의 마지막 프레임을 다음 샷의 I2V 입력으로 사용(chain_frames 옵션).
  - 모든 생성 작업은 비동기(큐) 처리, 진행률은 DB에 기록 후 SSE로 푸시.

4. 기능 요구사항
--------------------------------------------------------------------------------
  F-01 작업 생성: 시나리오 텍스트(선택), 이미지 파일 1~N장(선택), 옵션 제출.
       둘 다 없으면 400 오류.
  F-02 옵션: 해상도(width/height), 샷당 길이(초), fps, provider, chain_frames.
  F-03 시나리오 분해: LLM이 장면별 {prompt, duration, narration} 목록을 생성.
       LLM 미설정/실패 시 문단 단위 규칙 기반 분해로 대체.
  F-04 이미지 매핑: 업로드 이미지 i 를 샷 i 에 대응. 이미지가 샷보다 적으면
       마지막 이미지 또는 이전 샷 마지막 프레임을 사용.
       IMAGE_ONLY 모드는 이미지 1장당 1샷.
  F-05 영상 생성: provider 별 샷 영상 생성.
  F-06 합성: 샷 영상들을 동일 해상도/fps로 정규화 후 연결 → final.mp4.
  F-07 진행률: status(queued/running/succeeded/failed), progress(0~100), message.
  F-08 결과 조회/다운로드: 최종 MP4 및 샷 목록 제공.
  F-09 작업 목록 조회.

5. API 명세 (v1)
--------------------------------------------------------------------------------
  POST /api/jobs                 multipart/form-data
       scenario: str (opt), images: file[] (opt),
       width:int=832, height:int=480, seconds_per_shot:float=5, fps:int=16,
       provider:str (opt, 기본=서버 설정), chain_frames:bool=true
       -> 201 {id, status, mode, ...}
  GET  /api/jobs                 -> [Job...]
  GET  /api/jobs/{id}            -> Job (shots 포함)
  GET  /api/jobs/{id}/events     -> text/event-stream (진행률 SSE)
  GET  /api/jobs/{id}/video      -> video/mp4
  GET  /api/health               -> {status, provider}
  GET  /api/auth/check-username  -> {available, message} (계정 중복 검사)
  POST /api/auth/register        -> {id, username, verification_required, ...} (가입 & 인증 메일)
  POST /api/auth/verify-email    -> {success, message_ko, message_en} (이메일 6자리 코드 인증)
  POST /api/auth/login           -> {id, username, csrf_token}
  POST /api/auth/logout          -> 204
  POST /api/jobs/{id}/cancel     -> 작업 중지
  POST /api/system/shutdown      -> 프로그램 종료

  Job = {id, mode, status, progress, message, scenario, options, shots[],
         video_url, created_at, updated_at}

6. 비기능 및 UI 요구사항
--------------------------------------------------------------------------------
  - 다국어 인터페이스(i18n): 한국어 및 영어 실시간 전환 토글 지원.
  - 인증 화면 디자인: Google 로그인 스타일의 흰색 바탕 반응형 카드 폼.
    가입 시 계정 중복 검사, 국가/전화번호/이메일 입력. Python 애플리케이션·워커 메일 시스템(FastAPI / Celery / aiosmtpd 내장 포트 1025)을 통해 6자리 인증 코드 발송 및 실시간 인앱 메일 수신함 제공.
    코드 확인 성공 시 "인증되었습니다" (영문: "You are Verified") 메시지 표출 후 2초 뒤 로그인 화면 자동 전환.
  - 장시간 작업(수 분~수십 분) 대응: 비동기 큐, 작업 타임아웃 설정.
  - GPU 1장 기준 worker concurrency = 1.
  - 업로드 제한: 이미지 jpg/png/webp, 장당 20MB.
  - 개발 환경에서는 mock provider 로 GPU/ComfyUI 없이 전체 흐름 검증 가능.
  - 비밀값(API 키)은 .env 로 관리, 저장소에 커밋 금지.

7. 기술 스택
--------------------------------------------------------------------------------
  Server : Python 3.11, FastAPI, SQLAlchemy, Pydantic Settings
  Queue  : Celery 5 + Redis  (Windows 에서는 --pool=solo)
  Engine : ComfyUI + Wan 2.1, FFmpeg
  LLM    : Anthropic Python SDK (claude-opus-5-5), 미설정 시 규칙 기반
  Client : React TypeScript (Vite 빌드 후 FastAPI 가 정적 서빙)
